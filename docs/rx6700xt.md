## Environment adaptation

The machine has no Visual Studio linker, so the diagnostics build was made with
the installed GNU toolchain:

```powershell
$env:RUSTUP_TOOLCHAIN = '1.98.1-x86_64-pc-windows-gnu'
$env:TMP = 'C:\Users\guilh\Documents\gta_cyber_leek\_tmp'
$env:TEMP = $env:TMP
cargo build --locked --profile diag -p victory --features diagnostics
```

Result: build completed successfully in 1m30s. No source patch was needed for
the GNU build.

Derived cache and save data are isolated from the earlier upstream checkout:

- `C:\Users\guilh\Documents\gta_cyber_leek\victory-7900XTX` is the fork.
- `C:\Users\guilh\Documents\gta_cyber_leek\victory-data-6700xt` holds this
  branch's cache and data.

## Test log

The next section is updated from actual runs, including launch mode, peak
private memory, frame rate, loading stalls, shader failures and crashes.

### Initial safe-mode run (2026-11-25 22:52)

Command profile: upstream `scripts/play.ps1 -Safe` on the real RX 6700 XT.

- Boot, intro and menus: mostly 30 fps.
- Reached the game world without an out-of-memory error or crash.
- Peak sampled private memory: 23.7 GiB. The 31.6 GiB machine therefore has
  headroom, but little room for unrelated applications.
- World preparation produced 190 to 9,128 draws per frame and fell to 0-3 fps
  while pipelines and streamed data were prepared.
- The log contains no `ERROR` entries.
- Startup logged 29 unimplemented pipeline-creation slots and one dropped
  dispatch. These can omit effects or draws and need comparison against the fast
  profile.
- `scripts/play.ps1` passed the literal value `none` to
  `VICTORY_SKIP_PIPELINES`, which expects shader hashes. This produced a warning
  and did nothing useful.

The safe profile is a useful compatibility baseline, but it is not the profile
we want for play. It confirms that the full data set and this GPU can enter the
world on a 32 GiB machine.

## Changes made for this machine

1. Registered the supplied `1.0.2.1` Scarlett executable by BLAKE3 in
   `KNOWN_BUILDS`, so `victory.exe` no longer reports it as an unknown build.
2. Removed the invalid `VICTORY_SKIP_PIPELINES=none` default from the upstream
   play script.
3. Added `scripts/play-rx6700xt.ps1`:
   - detects physical and logical CPU counts;
   - gives the translator and joined submissions work matched to the six
     physical cores instead of the 7900 XTX machine's eight-core split;
   - keeps four mapping workers as the maximum on this CPU;
   - caps shadow-side card buffers at 2 GiB on the 12 GiB GPU;
   - defaults to the fast path and keeps `-Safe` for diagnosis.
4. Kept the game cache and saves in an isolated data tree under
   `victory-data-6700xt`.
